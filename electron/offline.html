WSL isn’t responding

      
MindFlock runs inside WSL (Ubuntu), and Windows
         can’t reach it right now. Restarting WSL usually fixes this.

      
      
Restarting closes anything else running in WSL.

         If it doesn’t help, restart your computer and reopen MindFlock — or, if
         WSL was only just set up, check wsl -l -v lists a distro.

      

    


    
    

      
Finish setting up WSL

      
Windows Subsystem for Linux is present, but it doesn’t have a working
         Linux distribution yet — so MindFlock’s engine has nowhere to run.

      
Open PowerShell and:

      
run wsl --install  →  restart your computer
          →  run wsl once to finish creating your Linux user.

      
When wsl drops you into a Linux shell, reopen MindFlock.

      
Already have a distro? Make sure wsl -l -v lists
         it (state Running or Stopped), then reopen MindFlock.

One more step

      
MindFlock isn’t set up in WSL
         (Ubuntu) yet.

      
This installs MindFlock’s engine under your home folder, then the
         tools your agents need (tmux and your coding agent). That last part
         may ask for your password once.

      
      
If macOS blocked the app: System
         Settings → Privacy & Security → Open Anyway.

         MindFlock is self-signed, so this happens once per install.

      
      
A one-time setup. MindFlock opens by itself and carries on from there.

    


    
    

      
Install Homebrew first?

      
MindFlock installs tmux (which runs your agents’ terminals) with
         Homebrew, and Homebrew isn’t on this Mac yet.

      
Install Homebrew opens Terminal and runs Homebrew’s official
         installer there — it asks for your password in that window. MindFlock
         carries on by itself when it’s done (a few minutes).

      
      
      
Skipping installs the engine only; Setup offers tmux again later.
